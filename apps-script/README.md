# เขียนตารางกะกลับลง Google Sheet

แก้ตารางกะในเว็บแอปแล้วให้ค่าไปเปลี่ยนในชีตจริง โดยผ่าน Google Apps Script Web App

เดิมแอปอ่านข้อมูลจากชีตทางเดียว (ผ่านลิงก์ publish ซึ่งเป็น read-only)
ส่วนนี้เพิ่มขาเขียนกลับ ทำให้ข้อมูลสองฝั่งตรงกันเสมอ

---

## ติดตั้ง (ทำครั้งเดียว ~5 นาที)

### 1. เปิด Apps Script ของสมุดงาน

เปิด Google Sheet ที่ใช้อยู่ → เมนู **ส่วนขยาย (Extensions)** → **Apps Script**

> ต้องเข้าจากในสมุดงานเท่านั้น เพราะสคริปต์ใช้ `getActiveSpreadsheet()`
> ถ้าสร้างโปรเจกต์ Apps Script แยกจะหาสมุดงานไม่เจอ

### 2. วางโค้ด

ลบโค้ดตัวอย่างในไฟล์ `Code.gs` ทิ้ง แล้ววางเนื้อหาทั้งหมดจาก
[`apps-script/Code.gs`](./Code.gs) ในโปรเจกต์นี้ลงไปแทน

### 3. ตั้งค่าลับ

แก้บรรทัดบนสุดของไฟล์ให้เป็นค่าของคุณเอง (อะไรก็ได้ที่เดายาก):

```javascript
var SHARED_TOKEN = 'CHANGE-ME-TO-YOUR-OWN-SECRET';
```

กด **บันทึก** (ไอคอนแผ่นดิสก์)

### 4. Deploy

**Deploy** → **New deployment** → เลือกชนิดเป็น **Web app** แล้วตั้งค่า:

| ช่อง | ค่าที่ต้องเลือก |
|---|---|
| Execute as | **Me** (บัญชีคุณ) |
| Who has access | **Anyone** |

กด **Deploy** → ครั้งแรกจะขอสิทธิ์เข้าถึงสมุดงาน ให้กด **Authorize access** และอนุญาต

> หน้าจอจะขึ้นเตือน "Google hasn't verified this app" เพราะเป็นสคริปต์ที่คุณเขียนเอง
> ให้กด **Advanced** → **Go to (ชื่อโปรเจกต์) (unsafe)** เพื่อไปต่อ

คัดลอก **Web app URL** ที่ได้ (ลงท้ายด้วย `/exec`)

### 5. ใส่ค่าลงในเว็บแอป

ในเว็บแอป กดปุ่ม **"ตั้งค่าเขียนกลับชีต"** บนแถบด้านบน แล้วใส่:

1. **URL** ที่คัดลอกมาจากขั้นที่ 4
2. **Token** ให้ตรงกับ `SHARED_TOKEN` ในขั้นที่ 3

เสร็จแล้วป้ายจะเปลี่ยนเป็น **"เขียนกลับชีตพร้อมใช้งาน"**

---

## วิธีใช้

| การกระทำ | พฤติกรรม |
|---|---|
| แก้กะทีละช่อง (คลิกแล้วกด `1` `2` `3` `A` `H`) | เขียนลงชีตอัตโนมัติ |
| ระบายกะเป็นช่วง | เขียนอัตโนมัติ รวมเป็นคำขอเดียว |
| แลกกะ | เขียนอัตโนมัติทั้งสองช่อง |
| **จัดกะอัตโนมัติ** | **ไม่เขียนเอง** — ป้ายจะขึ้น "ยังไม่ได้บันทึก N ช่อง" ต้องกดยืนยัน |

จัดกะอัตโนมัติสร้างตารางใหม่ทั้งเดือน ถ้าเขียนเองทันทีจะไปทับงานในชีตทั้งเดือน
โดยที่ยังไม่ทันได้ดู จึงตั้งใจให้ต้องกดยืนยันก่อน

การแก้หลายช่องติด ๆ กันจะถูกรวบเป็นคำขอเดียว (หน่วง 0.9 วินาที) ไม่ได้ยิงทีละช่อง

### ถ้าเขียนไม่สำเร็จ

ป้ายจะขึ้น **"บันทึกลงชีตไม่สำเร็จ"** พร้อมสาเหตุ (เอาเมาส์ชี้เพื่อดู)
การแก้ไขยังอยู่ในแอปและเดือนนั้นจะถูกล็อกไว้ ระบบจะไม่ดึงข้อมูลจากชีตมาทับ
กดที่ป้ายเพื่อลองบันทึกใหม่

## ข้อจำกัดที่ควรรู้

**Token นี้กันได้แค่การใช้งานผิดโดยบังเอิญ ไม่ใช่ระบบความปลอดภัยจริง**
เพราะ deployment ตั้งเป็น "Anyone" และ token ฝังอยู่ในหน้าเว็บฝั่งผู้ใช้
ใครที่เปิด DevTools ดูก็เห็นได้ ถ้าเว็บแอปเปิดสาธารณะ ใครที่ได้ทั้ง URL และ token
ไปจะเขียนลงชีตได้ ถ้าต้องการความปลอดภัยจริงจังต้องเปลี่ยนไปใช้ OAuth
หรือมี backend ของตัวเองมาถือความลับแทน

**ข้อจำกัดอื่น**

- สคริปต์เขียนได้เฉพาะแท็บของเดือนที่มีอยู่แล้ว ไม่สร้างแท็บใหม่ให้
- รับเฉพาะรหัสกะ `1 2 3 A H L V HT1 HT2 HT3` อย่างอื่นจะถูกปฏิเสธและรายงานกลับ
- วันที่เกินจำนวนวันจริงของเดือนจะถูกปฏิเสธ (กันไปเขียนทับคอลัมน์สรุปท้ายตาราง)
- หาแถวจากเลข `No.` ก่อน ถ้าไม่ตรงจึงเทียบชื่อ — ถ้าทั้งสองอย่างไม่ตรงจะข้ามและรายงานกลับ
- Google แคชลิงก์ publish ราว 5 นาที ดังนั้นหลังเขียนสำเร็จ ค่าในชีตเปลี่ยนทันที
  แต่ขาอ่านของแอปอาจยังเห็นค่าเดิมจนกว่าแคชจะหมดอายุ

## แก้ปัญหา

| อาการ | สาเหตุที่พบบ่อย |
|---|---|
| `ปลายทางไม่ได้ตอบเป็น JSON` | Who has access ไม่ได้ตั้งเป็น **Anyone** (Google ส่งหน้า login กลับมาแทน) |
| `token ไม่ถูกต้อง` | ค่าใน `SHARED_TOKEN` กับที่ใส่ในแอปไม่ตรงกัน |
| `ไม่พบแท็บของเดือน …` | สมุดงานยังไม่มีแท็บของเดือนนั้น |
| แก้โค้ดแล้วไม่มีผล | ต้อง **Deploy → Manage deployments → แก้ไข → Version: New version** ทุกครั้ง |
| ติด CORS ใน console | ฝั่งแอปต้องส่ง `Content-Type: text/plain` เท่านั้น (โค้ดในโปรเจกต์ทำไว้แล้ว) |

## ทดสอบสคริปต์โดยตรง

เปิด Web app URL ในเบราว์เซอร์ ถ้าติดตั้งถูกต้องจะได้:

```json
{"ok":true,"service":"CNO Shift Roster writer","ready":true}
```
